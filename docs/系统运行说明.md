## 1 系统组成

提交的 Harness 镜像只有一个入口：`python3 /app/harness.py describe|train|predict`。平台在每个检查点轮次调用一次 `train`，在评测时调用 `predict`。

| 位置（镜像内） | 内容 |
|---|---|
| `/app/harness.py` | SDK 固定入口，原样取自 `contest-harness-sdk-1.0.4/template/harness.py` |
| `/app/contest_submission.py` | 选手模块。只有一行转发：`from agent_harness.contest import TASKS, train, predict` |
| `/app/model_config.txt`、环境变量 `AGENT_HARNESS_MODEL`、镜像标签 `org.contest.model` | 提交的模型身份 `Qwen/Qwen3.8-27B`。只用于记录和核对：每轮把它和平台绑定的 `rnd.model_name` 一起写进记录，不一致时以平台为准。**镜像内不含 PyTRiO 密钥** |
| `site-packages/agent_harness/` | 本队 Harness，即三层系统：策略层、训练层、执行与支撑层。平台适配在 `contest.py` |
| `site-packages/contest_harness/` | 官方 SDK 1.0.4，未做修改 |
| `/opt/agent-harness/vendor/cpu-baseline/baselines/` | 官方 CPU NumPy MLP 训练器，来自 `cpu-b-rul-20261110-v1`，覆盖 A/B/C 三个 profile。系统只在它的 4 个插槽里换函数体；插槽保持默认时，产出的检查点与官方逐字节相同 |

工业模型始终是官方训练器产出的检查点。系统没有改网络结构、输入维度和检查点格式，每一轮都从平台给出的父检查点续训，Adam 状态、标准化统计量和 epoch 计数都保留。

## 4 输入与输出

**训练（`train`）**

| 方向 | 路径 / 帧 | 说明 |
|---|---|---|
| 输入 | stdin 的 `start` 帧 | 数据集代号、轮次、任务合同、父产物、`max_output_tokens`、资源限制 |
| 输入 | `/data/train.jsonl`、`/data/validation.jsonl`（只读） | 当前阶段的公开投影，每行 `{"id","inputs","answer"}`，可带 `meta`。梯度训练和拟合统计量只用训练集；验证集只用于测量和选择 |
| 输入 | `/previous`（只读） | 父产物。通过 `rnd.parent.path()` 读取，并核对摘要 |
| 输入 | `/state`（只读） | 上一轮保存的 `harness_state.json`。首轮可能不存在 |
| 输出 | `/workspace/round-<n>/candidates/<arm>/` | 候选产物：`checkpoint.npz`、`training.json`、`history.jsonl`，以及 `baselines/*.py`（含 `slots.py`，即本轮实际使用的训练代码）。由 `submit_candidate` 分块上传 |
| 输出 | `rnd.save_state` | `harness_state.json`，内容是已验证策略、节奏、逐轮账本和经验可信度 |
| 输出 | `round_complete` 记录 | 选中的产物、假设、改动摘要、理由、配置、种子、引用的历史记录号和模型调用号 |

**预测（`predict`）**

- 平台把选中的产物挂载到 `/model`，`CONTEST_ARTIFACT_PATH` 指向检查点文件。
- 每读一行 `{"task","inputs"}`，就先写出一行结果并刷新，然后才读下一行：
  - 分类输出 `{"outputs":[{"label":…,"score":…},…]}`，分数在 [0, 1] 内，最高分唯一；
  - 回归输出 `{"outputs":{"value":非负数}}`。
- 前向计算直接调用官方 `Model.predict`，特征按官方 `flatten` 展开。

## 5 每一轮做什么

```text
start 帧 ─▶ ① 读状态和历史 ─▶ ② 读数据结构 ─▶ ③ 选节奏 ─▶ ④ 开局实验（仅首轮）
        ─▶ ⑤ 续训候选 ─▶ ⑥ 本地配对测量 + 平台测量 ─▶ ⑦ 27B 决策 + 安全门 ─▶ ⑧ 保存状态并结束
```

1. **读状态和历史**：读取 `/state/harness_state.json` 和 `rnd.history()`。
2. **读数据结构**：只看训练集的 `meta` 和输入，自动识别以下特征，不写死任何字段名。平台给的数据**每行只有 `id`、`inputs`、`answer`**，没有 `meta`；这时按答案的排列顺序找回设备：同一台设备的剩余寿命逐行减少一个固定步长（N−1, N−2, …, 0），递减链断开处就是换了下一台设备。在去掉 meta 的公开数据上，B 的 9 + 3 根轴承、C 的 496 + 106 台发动机全部切分正确：
   - 有没有设备，比如 B 的 `bearing`、C 的 `source_subset+unit`；
   - 答案是不是倒计时；
   - 数据流格式：`independent`、`sequence` 或 `snapshot`；
   - 验证输入相对训练输入的新颖度。
3. **选节奏**：
   - 没有设备结构 → `adaptive`（A）；
   - 倒计时 + 设备 + `sequence` → `event`（B、C）；
   - 上一轮没有晋升，且数据没变或输入已被覆盖 → `conserve`，续训轮数降到 2。
4. **开局实验（仅首轮）**：在训练集上做按设备分组的 3 折实验，整台设备留出，从不使用验证集。逐个检验经验库建议的算子：
   - 按设备 / 按类别封顶（E-cap、E-class-balance）；
   - 说长了加罚（`asymmetric_overestimate`、`_x4`）；
   - 相对误差加权（`relative_error`）；
   - `huber`；
   - 稀有类加权；
   - 标签平滑。

   前 2 折没有收益就停（无望即停）。通过的算子中，数据层和代码层各取最优；两者组合只有在超过单个算子时才一起生效。结果写进状态，后续轮次直接沿用。
5. **续训候选**：每个候选都从父检查点续训。
   - `control`：官方代码与配置，作为对照；
   - `strategy`：开局验证通过的数据配方加训练插槽。只有存在已验证策略、且节奏不是 `conserve` 时才训练。
6. **测量**：
   - 每个候选提交给平台测量；
   - 本地同时在公开验证集上计算它和父模型的配对差，并按设备做 bootstrap 估计 sd。设备少于 5 台时，按小样本放宽。
7. **27B 决策 + 安全门**：
   - 把情境特征、开局实验结果和候选的收益 / sd / 训练量发给 Qwen3.8-27B（经宿主网关，`enable_thinking=False`，单次 ≤ 400 Token），由它在候选中选择；
   - 只有父模型，或在验证集上不差于父模型的候选，才在安全集合内；
   - 安全集合：父模型，加上收益超过 0.5 个 sd 的候选；任务合同含 NASA 非对称评分时，候选的 NASA 不得比父模型差 20% 以上（防止用微小的 RMSE 收益换来严重的"说长了"）；
   - 27B 的选择不在安全集合内，或回复不是合法 JSON 时，采用规则：安全且收益超过 1 个 sd 才晋升，否则保留父模型。
8. **数据没变就不训练**：父模型、训练集、验证集都和上一轮逐字节相同，且上一轮保留了父模型时，续训只会重复上一轮已被拒绝的候选（训练是确定性的）。这时本轮不训练，仍调用一次 27B，由它确认保留父模型。
9. **保存状态并结束**：写入逐轮账本，更新经验可信度（有收益 +0.05，无收益 −0.1），然后 `finish`。`model_call_ids` 只引用本轮真实调用号。

## 6 配置参数

| 参数 | 默认值 | 作用 |
|---|---|---|
| `BASELINE_CPU_THREADS` | 1 | 官方训练器的 BLAS 线程数（1–8） |
| `AGENT_HARNESS_BASELINE` | `/opt/agent-harness/vendor/cpu-baseline` | 官方训练器位置 |
| `CONTEST_WORK` | `/workspace` | 可写工作目录（本地测试时改到临时目录） |
| `CONTEST_PREVIOUS` | 未设置，即 `/previous` | 只在本地测试时改父产物的挂载点 |
| `OPENING_FOLDS` / `OPENING_ROWS` | 3 / 6000 | 开局实验折数、每折训练行数上限（开局实验要计入算力成本） |
| `FUTILITY_FOLDS` | 2 | 前 2 折无收益即停 |
| `ROUND_EPOCHS` / `CONSERVE_EPOCHS` | 5 / 2 | 每个候选续训轮数（`conserve` 节奏时为 2） |
| `SELECTION_Z` | 1.0 | 规则晋升门槛：收益大于 1 个 bootstrap sd |
| `BOOTSTRAP_REPS` | 200 | 按设备 bootstrap 次数 |
| `CAP_IMBALANCE` | 3.0 | 组大小超过中位数的 3 倍时，才尝试封顶 |
| `SAFE_Z` | 0.5 | 安全集合门槛：收益大于 0.5 个 bootstrap sd 的候选才允许 27B 选择 |
| `NASA_TOLERANCE` | 0.2 | 任务合同含 NASA 时，候选 NASA 最多比父模型差 20% |
| `REPLY_TOKENS` | 400 | 27B 单次回复上限（不超过平台给的 `max_output_tokens`） |
| 开局时间预算 | `wall_seconds` 的 45% | 超时后跳过剩余开局实验，保证上传和结束有时间 |

后六项是 `src/agent_harness/contest.py` 顶部的常量，全部用公开数据定。离线评测用的规则参数在 `configs/policies/default.yaml`，经验库在 `configs/experiences/seed.yaml`。

## 9 异常处理与回滚

| 情况 | 处理 |
|---|---|
| 开局实验出错或超时 | 记入状态（`failed`），本轮只训练官方对照候选，流程不中断 |
| 所有候选都不优于父模型 | `finish` 选父产物 `rnd.parent.artifact_id`，模型保持不变 |
| 数据没有 `meta`（平台投影） | 按答案顺序找回设备；答案不构成递减链（如分类任务）时按独立样本处理 |
| 数据与父模型都没变 | 本轮不训练，调用一次 27B 后保留父模型 |
| 27B 回复不是 JSON，或选择越出安全集合 | 采用规则选择，理由里写明"规则选择"和模型的原始选择 |
| 状态文件损坏或版本不符 | 从空状态开始，相当于重新开局 |
| 平台重试同一轮 | 工作目录自动换成 `round-<n>-2` 等新目录，不复用写了一半的文件 |
| RPC 被中断（`RPC_OUTCOME_UNKNOWN`） | 按 SDK 要求不捕获、不重试，本轮以 `round_failed` 结束，由平台处理 |
| 父产物摘要不符（`PARENT_DIGEST_MISMATCH`） | 由 SDK 抛出，本轮失败，不会在错误的起点上训练 |
| 预测时特征结构与检查点不一致 | 报错退出，不输出猜测值；分类时出现并列最高分，会把后者下调一个最小浮点间隔，回归值截断为非负 |

**回滚**：

- 平台保存每一轮提交的全部产物。下一轮只要选父产物或更早的产物（`rnd.restore_artifact`），就等于回滚。
- 系统不覆盖任何已有检查点。官方训练器的输出目录必须是新目录，候选目录也是每轮新建。
- 每个候选都带着训练它的 `baselines/*.py` 和 `training.json`（含父检查点摘要、步数、源代码摘要），可以逐字节复现。

## 10 合规要点

- 只从平台给出的父检查点续训，不另造历史哈希，也不搜索 `/app` 找权重。
- 公开验证集只用于测量和选择，不进入梯度训练。开局实验只用训练集，按设备留出。
- 每轮至少调用一次平台模型，`model_call_ids` 只引用真实回执号。
- stdout 只写协议帧，日志一律写 stderr，以 `[harness]` 开头。
- 源码包和镜像都不含隐藏测试集、密封数据（`data/sealed`）和任何账号密钥。
