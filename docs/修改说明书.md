# 修改说明书（算子手册）

系统改变“怎样训练、采用哪个模型、怎样上线”的**唯一**方式，是调用下列算子。经验库、确定性兜底分析器和大模型都用这套名字，监督器按本手册校验参数、判断收紧或改进、选择验证方式并执行。本文件由 `src/agent_harness/operators.py` 自动生成，代码即手册。

## 不变的部分

官方训练器的核心不是算子，永远不变：网络结构（单隐层、tanh、宽度）、数据标准化参数、Adam 常数、梯度与特征裁剪、训练循环、数据解析、检查点格式、随机种子。

## 生效规则

- **probation**：整套节奏：依据数据特征立即生效，随后进入观察期，按实际表现判定，变差就整体撤销（重放无法比较节奏，因为不同节奏购买的标注不同）
- **none**：收紧或节奏类修改：立即生效，无需验证
- **fixed**：比较模型质量：开局用训练集按组 k 折（从头训练），运行中用固定流程重放已发生的批次（每批都训练、都上线）
- **full**：比较选择规则：运行中用完整流程重放已发生的批次（含门槛与上线逻辑）
- **unverifiable**：运行中无法验证（重放只能使用当时已购买的标注），放宽方向一律不采纳
- **收紧 / 改进的判定**：同一个算子按方向决定，例如 `gate.z` 调高是收紧、调低是改进；`serve.*` 按 试用 < 影子 < 暂停 的顺序，往后是收紧。
- **占位符**：`$entity`（识别出的设备字段）、`$order`（顺序字段）、`$median_group_size`（中位设备行数）、`$median_class_size`（中位类别行数），在每个任务上按其数据自动填值，所以同一条经验可以跨任务套用。
- **撤销**：每次修改生成一个策略版本；观察期不通过时整体退回上一版本。
- **节奏（`mode.*`）**：一次设定检验时机、训练时机、上线方式和标注抽取方式。三种节奏对应三类数据——答案及时且输入在变（积极跟随）、答案要等设备跑完（设备完成时更新）、输入不变且更新无收益（节省）。选哪一种由经验库里带条件的经验根据情境特征决定（`configs/experiences/seed.yaml`），运行中特征变化时监督器触发“情境与节奏不符”（T10）重新选择。每轮最多切换一次节奏。

## 训练节奏

### `mode.adaptive` —— 切换为“积极跟随”节奏

答案当批就到、输入在变化且更新有收益时：当批全部新答案（连同官方训练集和历史）训练一个候选，直接试用；下一批的新答案确认它或回退。没有当批拆分，也不在当批过门槛，适应最快。

| 项 | 内容 |
|---|---|
| 参数 | `fraction`（fraction float [0.05, 1] 默认 0.5）：每批请求标注的比例 |
| 收紧还是改进 | 节奏：立即生效，观察期判定 |
| 验证 | 整套节奏：依据数据特征立即生效，随后进入观察期，按实际表现判定，变差就整体撤销（重放无法比较节奏，因为不同节奏购买的标注不同） |
| 成本影响 | 每批训练一次（一个候选） |
| 撤销 | 观察期不通过时退回切换前的整套策略 |
| 适用条件 | 任何任务 |
| 调用示例 | `{"operator": "mode.adaptive", "params": {}}` |

### `mode.event` —— 切换为“设备完成时更新”节奏

答案要等设备（实体）跑完才有时：设备运转期间不训练；某台设备跑完时，用它（没人训练过）检验“用其余全部数据训练的候选”，更好才用全部数据重训并上线。标注沿时间均匀少买（同一设备相邻行几乎相同）。

| 项 | 内容 |
|---|---|
| 参数 | `fraction`（fraction float [0.05, 1] 默认 0.25）：每批请求标注的比例 |
| 收紧还是改进 | 节奏：立即生效，观察期判定 |
| 验证 | 整套节奏：依据数据特征立即生效，随后进入观察期，按实际表现判定，变差就整体撤销（重放无法比较节奏，因为不同节奏购买的标注不同） |
| 成本影响 | 只在设备完成时训练 |
| 撤销 | 观察期不通过时退回切换前的整套策略 |
| 适用条件 | 数据有设备（实体）结构 |
| 调用示例 | `{"operator": "mode.event", "params": {}}` |

### `mode.conserve` —— 切换为“节省”节奏

输入不变、更新没有收益时：暂停训练，少买标注（只用于监控）；环境突变或低于基线时监督器会重新打开。

| 项 | 内容 |
|---|---|
| 参数 | `fraction`（fraction float [0.05, 1] 默认 0.1）：每批请求标注的比例 |
| 收紧还是改进 | 节奏：立即生效，观察期判定 |
| 验证 | 整套节奏：依据数据特征立即生效，随后进入观察期，按实际表现判定，变差就整体撤销（重放无法比较节奏，因为不同节奏购买的标注不同） |
| 成本影响 | 训练量降为 0，标注减少到 10%（只用于监控） |
| 撤销 | 观察期不通过时退回切换前的整套策略 |
| 适用条件 | 任何任务 |
| 调用示例 | `{"operator": "mode.conserve", "params": {}}` |

默认节奏：当批一半答案训练、另一半检验，过门槛才试用，下一批确认。

## 标注采购

### `label.sampling` —— 选择标注的抽取方式

random：随机抽取；spread：沿时间均匀抽取（同一设备相邻行高度相关时，信息相同而标注更少）。

| 项 | 内容 |
|---|---|
| 参数 | `method`（method random|spread 默认 spread）：抽取方式 |
| 收紧还是改进 | 节奏：立即生效，观察期判定 |
| 验证 | 整套节奏：依据数据特征立即生效，随后进入观察期，按实际表现判定，变差就整体撤销（重放无法比较节奏，因为不同节奏购买的标注不同） |
| 成本影响 | 不变 |
| 撤销 | 恢复修改前的方式 |
| 适用条件 | 任何任务 |

### `label.fraction` —— 调整每批购买标注的比例

每批数据中请求标注的比例。降低能直接节省标注成本，但会减少可用于训练和检验的数据。

| 项 | 内容 |
|---|---|
| 参数 | `fraction`（fraction float [0.05, 1]）：每批请求标注的比例 |
| 收紧还是改进 | 调低为收紧，调高为改进 |
| 验证 | 运行中无法验证（重放只能使用当时已购买的标注），放宽方向一律不采纳 |
| 成本影响 | 标注量随比例同向变化 |
| 撤销 | 恢复修改前的比例 |
| 适用条件 | 任何任务 |
| 调用示例 | `{"operator": "label.fraction", "params": {"fraction": 0.3}}` |

## 训练代码插槽的内置实现

| 插槽 | 名字 | 适用任务 | 假设 |
|---|---|---|---|
| `sample_weights` | `sqrt_inverse_class_frequency` | classification | Rare classes dominate Macro-F1 but barely move the mean loss; weight samples by 1/sqrt(class count) so every class contributes comparably without extreme weights. |
| `sample_weights` | `target_range_balance` | regression | Long-lived units contribute most rows, so short remaining lives are under-weighted; balance ten equal-width target bins with 1/sqrt(bin count) weights. |
| `loss_and_delta` | `asymmetric_overestimate` | regression | Over-estimating remaining life is the dangerous error (NASA score penalises it more); double the squared-error weight of over-estimates. |
| `loss_and_delta` | `asymmetric_overestimate_x4` | regression | A single observation rarely tells how long a unit will last, so short remaining lives are read as average ones and over-estimated; weight the squared error of over-estimates four times. |
| `sample_weights` | `relative_error` | regression | Rows far from the end dominate the squared error although they carry the least information; weight rows by 1 / (target above its minimum + the median of that), i.e. by relative rather than absolute error (invariant to the target scaling). |
| `loss_and_delta` | `huber` | regression | Run-to-failure targets have heavy tails; a Huber loss (delta = 1 target std) limits the pull of the largest residuals. |
| `loss_and_delta` | `label_smoothing` | classification | Drifting sensors make the network over-confident on stale boundaries; 5% label smoothing keeps logits from saturating. |
| `regularizer_gradients` | `l2_1e-4` | classification, regression | Weights keep growing during continued training; mild L2 (1e-4) on w1/w2 limits it. |
| `regularizer_gradients` | `l2_1e-3` | classification, regression | Validation degrades while training loss falls; stronger L2 (1e-3) trades fit for stability. |
| `learning_rate` | `inverse_time_decay` | classification, regression | Continued training from a converged checkpoint overshoots; decay the rate as 1/(1+step/2000). |
