  - 逐批指标：效用、静态模型效用、相对静态的增益、标注数、晋升；

## 1 大模型使用说明（如实声明）

| 项目 | 说明 |
|---|---|
| 模型 | **基础模型 `Qwen/Qwen3.8-27B`**（PyTRiO 平台白名单）。**没有微调**，没有持久化 Sampler 权重，没有 `trio://` 路径 |
| 比赛中的调用方式 | 镜像内调用 `rnd.model()`，经平台宿主网关转发。密钥和端点由平台持有，镜像、源码和本记录中都不含密钥 |
| 每轮的用途 | 每个检查点轮次调用 **1 次**，读入情境特征、开局实验结果和各候选的收益 / 波动 / 训练量，从候选和父模型中选一个，并给出理由 |
| 调用参数 | `max_tokens ≤ 400`、`temperature = 0`、`enable_thinking = False` |
| 安全门 | 27B 只能从安全集合里选，安全集合是父模型加上不差于父模型的候选。越界或回复无法解析时，改用规则选择，理由里写明 |
| 不让大模型做的事 | 不改网络结构、不碰隐藏数据、不直接写工业模型权重。工业模型始终是官方 NumPy MLP 训练器续训得到的检查点 |

**接入实测**（2026-11-24，B 数据集，两轮，在镜像内经 PyTRiO 调用 `Qwen/Qwen3.8-27B`）：

| 轮次 | 局面 | 27B 的选择 | 与规则 | Token（输入 + 输出） | 思考 Token | 延迟 |
|---|---|---|---|---|---|---|
| 1 | 策略候选 RMSE −43.0 分钟（sd 15.1） | 采用策略候选 | 一致 | 784 + 54 | 0 | 2.6 s |
| 2 | 两个候选都变差（−49、−43） | 保留父模型 | 一致 | 557 + 50 | 0 | 1.9 s |

## 2 工业模型训练记录

- **训练器**：官方 `cpu-b-rul-20261110-v1/baselines`（单隐层 tanh MLP + Adam），覆盖 A/B/C 三个 profile。系统只在 4 个插槽里换函数体：样本权重、损失、正则、学习率。插槽保持默认时，产出的检查点与官方逐字节相同（有单元测试保证）。
- **平台上的每一轮**：每个候选都从父检查点续训，Adam 状态、标准化统计量和 epoch 计数都保留。随每次 `submit_candidate` 上报的内容有：
  - 假设和改动摘要；
  - 配置：节奏、数据配方、插槽版本、轮数、学习率、训练行数、父 / 子检查点摘要、本地配对测量；
  - 种子。

  `finish` 再上报选中的产物、理由、27B 调用号和引用的历史记录。这些记录由平台保存。
- **候选产物**：每个候选目录都带着训练它的 `baselines/*.py`（含 `slots.py`）、`training.json`（含源代码摘要和父检查点摘要）和 `history.jsonl`（逐 epoch 记录），可以逐字节复现。

## 3 离线实验时间线

只用公开数据：官方检查点作为起点，把公开验证集按原始顺序切成若干批，模拟数据流。

| 日期 | 阶段 | 主要实验与结论 |
|---|---|---|
| 11-13 | 需求解读、实测驱动设计 | 不更新的模型在 A 上从 0.96 跌到 0.19；在刚训练过的数据上评估，候选会被高估 0.28；不按设备分组，噪声会被低估 21 倍 |
| 11-13 | 框架第一版 | 官方训练器 + 插槽，不可变检查点树，晋升要超过波动、下一批确认后才转正 |
| 11-14 | 第二版：agent 先探索、再给方案 | 接通 27B，发现它能看出问题，但很少落成具体修改，一次运行约 20 万 Token |
| 11-14 | 修改说明书、经验库 | 32 个算子（9 类）；经验写成"情境条件 → 算子调用" |
| 11-14 | 第三版：三种训练节奏 | adaptive / event / conserve，由情境特征和经验选配 |
| 11-15 | 第四版：统一 pipeline | 开局实验有预算并计入成本、累计确认、最短停留期、27B 只在规则不够用时出场（每次运行 ≤ 3 万 Token） |
| 11-24 | 平台接入（SDK 1.0.4） | 逐轮适配层、Docker 镜像、断网测试、PyTRiO 真实调用测试 |

我们曾报告过一个"B 提升 69.5 分钟"的结果，后来自查发现，模拟时提前拿到了答案，已主动撤回。

## 4 关键结果（第四版，公开数据，3 个种子）

"相对不更新"是每批与官方模型之差的平均，括号里是波动范围。A 用 Macro-F1，越高越好；B、C 列的是 RMSE 的降低量，正数表示更好。

| 数据流 | 无脑更新 | 只有训练层 | **完整系统** | 完整系统成本 |
|---|---|---|---|---|
| A（4 批） | −0.024（0.026） | 0 | −0.024（0.026） | 4.9 万行×轮，622 条标注 |
| A_long（12 批） | −0.004（0.011） | −0.005（0.007） | −0.002（0.011） | 5.4 万行×轮，476 条标注 |
| **B 设备跑完才给答案** | **−17.0（3.8）** | 0 | **+52.8（29.5）** | 182 万行×轮（其中开局实验 178 万），300 条标注 |
| C（11 批） | +0.44（0.51） | 0 | 0 | 36 万行×轮，2,306 条标注（训练层 11,523） |
| C_snapshot（16 批） | +0.74（0.72） | 0 | 0 | 36 万行×轮，32 条标注 |

- **27B 组**：分数与规则兜底版相同。每次运行用 2,400–20,500 Token，第三版是 2.3 万–9.5 万。
- **留一任务验证**：先在两个任务上积累经验，再跑第三个任务。结果与空经验库完全相同，说明决策来自通用的情境规则，不依赖记住某个任务。
- **换字段名测试**：把字段全部改名后，结构识别和决策不变。

## 5 冻结后的一次性核验

第四版冻结后（配置指纹 `fef8ccc24b5bb27e`），在主办方未公开的数据流上**只核验一次**：
- 参数全部由公开数据确定，不据核验结果调参；
- 在临时目录运行，跑完删除运行目录，避免保留隐藏数据的派生文件，所以没有逐批运行记录，只有汇总结果。

| 数据流 | 结果 |
|---|---|
| B 三根隐藏轴承 | RMSE 581 → 224 分钟（−61%）；无脑更新和只有训练层几乎没动 |
| C | 与不更新相差在 ±2% 内，标注少 80% |
| A | 完整系统 +0.249，无脑更新 +0.312（系统略低，原因是安全网按单批回退偏谨慎） |
| 27B | Token 降到第二版的约 2%，分数从 0.173 升到 0.249 |
